发布检查清单（每次发布前逐项核对）
========================================

【第 0 步：推代码前，先自己看一眼】
□ git status        —— 确认改了哪些文件，没有意外文件混进来
□ git log --oneline —— 确认要推的提交信息写得规范、清楚

【第 1 步：挡三样东西（安全红线）】
□ API key / .env / 密码文件  绝对不进仓库（.gitignore 已配好，别手动绕过）
□ __pycache__ / 临时文件     由 .gitignore 管住
□ .exe 大文件                走 Releases；根目录只留最新一份“字幕工坊_安装与启动.exe”给小白
（winsecret.py 是安全的，密钥用 Windows DPAPI 加密，只存本机，可放心提交）

【第 2 步：数字一致性（忠告第 5 条）】
□ README 里的测试数量 = 实际测试数量（当前：Python 86 项 + C# 23 项）
□ README / 更新记录 / VALIDATION 里的 FAQ 条数一致（当前：120 条）
□ 任何地方都不许出现“81 项”“85 项”“114 条”等旧数字
   （核对方法：跑一遍 python -m unittest discover -s tests -p "test_*.py" 看 Ran 多少）

【第 3 步：README 顶部下载按钮】
□ 下载链接指向最新的 Release（不是旧版、不是 Code 里的 ZIP）

【第 4 步：版本号与更新记录】
□ 更新记录.txt 写清楚本次改了什么（新功能 / 修 bug / 文档）
□ 版本号（如 1.6+）与 README、manifest.json 里的一致

【第 5 步：构建产物】
□ 重新生成 SHA256SUMS.txt（source\sha_sums.py）并提交
□ 最新一份“字幕工坊_安装与启动.exe”已放到根目录

【第 6 步：GitHub Release】
□ 在 GitHub 上创建/更新 Release，上传完整 ZIP 包
□ Release 版本号与更新记录一致
□ 附上 SHA256SUMS.txt 校验文件

【第 7 步：releases/latest 链接】
□ 小白指南、README 里指向 releases/latest 的下载链接是最新的
□ 确认“第一次安装”章节的步骤对得上最新包

【推送命令（本机）】
git status
git add .
git commit -m "feat: xxx / fix: xxx / docs: xxx"
git pull --rebase origin main   （有冲突就解决冲突）
git push origin main

========================================
记住：上面任何一项漏了，小白就可能迷路。
